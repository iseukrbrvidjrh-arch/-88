## 1. 功能目标

不是新增功能，而是证明已有功能**在异常、边界和真实数据下仍然正确**：

- 跑通 SRS 的关键验收测试（AT 列表）。
- 完成异常矩阵、隐私与安全、性能基线、迁移与备份演练。
- 输出可核对的验收报告：哪些通过、哪些未达标准、证据是什么。

## 2. 相关需求编号

- 全部 NFR（NFR-001 ~ NFR-020）
- EX-001 ~ EX-033 异常场景

## 3. 涉及模块

- 全部模块（只做验证与必要修复，不新增功能）
- `reports/`：验收报告与证据
- `tests/`：补充端到端与回归测试

## 4. 输入与输出

**输入**

- 已完成的实现与测试套件。
- 固定测试数据：自制字幕样本（含缩略、所有格、连字符、带点缩写、无效 cue、重复内容、大文件）。
- 受控时钟与假网关。

**输出**

- 验收报告：AT 逐条结果、证据（命令输出/截图）、未通过项与原因。
- 异常矩阵执行记录：每条异常的实际表现与预期对照。
- 性能记录：导入、列表、复习提交的实测值（注明机器与数据规模）。
- 安全记录：CSP/Host/Origin/token 验证、日志扫描、仓库密钥扫描、抓包确认无意外外联。
- 迁移与备份演练记录：升级、失败、恢复。

## 5. 技术约束

1. 只修复与本轮验收直接相关的缺陷；发现新需求先报告，不自行实现。
2. 性能不达标时如实记录，不修改目标数字、不伪造数据。
3. 隐私检查必须实际观察：抓包或等价手段确认除用户主动触发的千问请求外无外联。
4. 密钥扫描覆盖仓库、日志、数据库、前端构建产物。
5. 验收测试必须可重复执行；依赖外部网络或 Key 的用例需标注并默认跳过，人工验收时单独执行。
6. 修复缺陷时不得改变已批准的业务规则；如需变更规则，停止并报告。
7. 报告中不得包含 API Key、完整字幕内容或个人路径。

## 6. 实现边界

**做**

- 补充测试、修复缺陷、性能测量、隐私与安全核查、迁移与备份演练、验收报告。

**不做**

- 不新增功能、不做 P1。
- 不做视觉重构。
- 不改需求、架构或数据模型；发现必须改时报告并由用户决策。
- 不做发布打包、签名、自动更新（未在需求内）。

## 7. 自动化测试要求

1. AT-001 ~ AT-023：能自动化的全部自动化；不能自动化的列入人工清单。
2. 异常矩阵：EX-001 ~ EX-033 逐条有对应用例或明确的人工验证步骤。
3. 回归：TASK-001 ~ TASK-012 的测试全部仍通过。
4. 幂等：重复提交复习、重复执行发送计划、重复导入、重复保存，各有用例。
5. 时钟与日期：跨日、跨时区、时钟回拨（按 OI-17 的处理）各有用例。
6. 大文件与大批量：10 MB / 20,000 cue 边界与超限路径。
7. 安全：XSS、命令注入、路径穿越、Host/Origin/令牌、日志脱敏。
8. 数据一致性：统计与明细、状态与历史、删除与快照。

## 8. 人工验收标准

1. 按报告逐步执行：安装依赖、启动、导入、加词、复习、翻译、AI 问答、删除会话、归档/删除字幕。
2. 断网后完成本地闭环；联网后云端功能按预览发送。
3. 用抓包工具确认：除用户确认的千问请求外，无其他外联；请求中无 Key、无整部字幕。
4. 关闭应用、重启、再次关闭：数据完整、无重复记录、无残留进程。
5. 检查日志与仓库：无 Key、无完整字幕、无个人路径。
6. 读验收报告：每条 AT 有结果与证据；未达标项有影响说明与建议。
