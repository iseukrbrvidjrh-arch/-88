## 1. 结论摘要

### 1.1 总体判断

新方向与 SceneLingo 的核心目标一致，核心闭环“字幕导入 → 翻译和发音 → 千问 AI 交流 → 收藏学习 → 间隔复习 → 进度记录”在 SRS 中已有对应需求。当前 SRS 的主要问题不是“缺很多功能”，而是：

1. 有几项已被你提升为 MVP 的功能，SRS 仍标为 P1；
2. 有一项新要求（字幕归档/删除）在 SRS 中完全没有对应 FR；
3. 有两项新要求（模型配置、费用记录）只在 OI 中提及，没有形成可验收需求；
4. AI 上下文“自动携带会话历史”与新方向“仅发送明确授权的必要上下文”冲突；
5. 复习间隔 60/120/180 天与新方向“1/3/7/14/30 初始配置”冲突；
6. 统计口径中的“缩写”没有定义清楚，可能导致统计结果不可复现。

### 1.2 建议的结构性变化

| 变化 | 内容 | 状态 |
| --- | --- | --- |
| 提升 FR-022 | 语境解释从 P1 提升为 P0 | 待用户批准 |
| 调整 FR-071 | 自由问答从 P1 提升为 P0；短语比较保留 P1 | 待用户批准 |
| 新增 FR-018 | 字幕归档/删除与孤立记录防护 | 待用户批准 |
| 新增 FR-091 | 千问模型配置与经济型模型选择 | 待用户批准 |
| 新增 FR-092 | 千问调用费用记录/估算 | 待用户批准 |
| 调整 BR-REV-04 | 初始间隔改为 1/3/7/14/30 天；更长间隔作为后续实验 | 待用户批准 |
| 调整 BR-AI-03/FR-072 | 默认不自动发送会话历史；改为显式授权 | 待用户批准 |
| 修订 BR-SUB-08 | 明确缩写、连字符、所有格、带点缩写的规则 | 待用户批准 |

### 1.3 不建议做的事

- 不把商业化、账号同步、复杂发音评分、视频播放加入 MVP。
- 不把“短语比较”“英文表达练习”“词条归档”“复习会话总结”“备份”自动提升为 P0；它们不在本次新方向的核心闭环内。
- 不为统计引入完整 NLP、词形还原、命名实体识别或大型停用词工程。
- 不为了让“费用记录”精确到分而承诺无法保证的账单金额；只能做“记录/估算”，并标注不确定性。

### 2.1 一个需要澄清的“造句”

新方向同时出现：

- “重新造句”（AI 改写句子）；
- “AI 聊天支持……造句”；
- 原 README 中的“英文表达练习”。

这三者可能不是同一件事：

1. **AI 重新造句**：AI 给出替代表达，属于 FR-071 的 P0。
2. **用户自己造句**：用户写英文句子，属于 FR-063 英文表达练习，当前 P1。
3. **自由问答中的造句示例**：AI 在回答里给例句，不是独立练习。

建议：MVP 只要求 1 和 3；2 保持 P1，除非你明确要“用户写句子并记录”。这是范围决策，不是技术问题。

SRS V0.1 共 52 条 FR：

- P0：48 条；
- P1：4 条（FR-022、FR-057、FR-063、FR-068）；
- FR-071 为 P0，但包含 P1 子项（自由问答、短语比较）。

- 提升 FR-022、FR-071 的自由问答为 P0；

### 3.5 新增/变更需求的建议验收条件

现有 52 条 FR 均有对应验收条件；以下只列本次新增或语义发生变化的部分。编号为建议编号，正式编号在 SRS V0.2 中分配。

#### FR-018 字幕归档/删除

- **AC-018-1**：归档字幕后，该字幕从默认字幕库隐藏，但可通过“已归档”筛选找到并恢复；关联词条、复习历史、语境引用不被删除。
- **AC-018-2**：无关联词条/复习记录的字幕可硬删除；确认后字幕消失，列表和统计相应更新，不产生错误引用。
- **AC-018-3**：存在关联词条/复习记录时，硬删除默认被阻止，并说明原因；用户只能选择归档，或明确确认“删除字幕但保留冻结语境快照”。
- **AC-018-4**：选择冻结语境快照后，词条详情仍显示原 cue 文本、字幕标题和“来源已删除”标记；复习历史仍可打开；不出现空白或报错。
- **AC-018-5**：取消删除/归档操作后，字幕、词条、历史均不发生变更；任何路径都不得静默级联删除学习记录。

#### FR-021 单词释义来源

- **AC-021-1**：本地词典命中时，直接显示释义/音标/例句和词典来源，不发起网络请求。
- **AC-021-2**：本地词典未命中时，明确显示“本地未收录”，不静默调用千问；用户可主动选择 AI 释义。
- **AC-021-3**：选择 AI 释义后，发送前预览只含该词和必要上下文；结果标注 AI 来源并缓存。
- **AC-021-4**：AI 失败时保留“本地未收录”状态，不把失败结果缓存为成功。

#### FR-015 重复导入

- **AC-015-1**：检测到重复字幕时，默认拒绝导入并显示重复项；原字幕、词条、历史不变。
- **AC-015-2**：用户取消重复提示后，不产生新字幕、新统计或新词条。
- **AC-015-3**：“作为新副本导入”为 P1；MVP 不以该能力作为验收条件。

#### FR-022 语境解释

- **AC-022-1**：用户选中 cue/词并点击解释后，预览显示将发送的确切文本；未确认前不发起千问请求。
- **AC-022-2**：请求只包含选中的 cue/词和必要提示，不包含整部字幕、其他字幕、复习历史或密钥。
- **AC-022-3**：成功结果标注“AI 生成”、模型和时间；结果可缓存并在再次打开时显示来源，不重复自动请求。
- **AC-022-4**：超时、限流、拒绝或网络失败时，保留原文并显示可理解错误；不得把失败结果缓存为成功。
- **AC-022-5**：选中文本、悬停或切换 cue 本身不触发云端请求；只有用户明确点击并确认后才请求。

#### FR-071 自由问答（P0 部分）

- **AC-071-1**：用户可输入自由问题并获得 AI 回答；回答标注 AI 生成，不自动执行任何本地操作。
- **AC-071-2**：自由问答仍遵守上下文选择、发送预览和首次同意；不能绕过云端调用闸门。
- **AC-071-3**：语法解释、重新造句、短文生成、纠错四类任务仍可用；自由问答不替代这些任务。
- **AC-071-4**：请求失败或用户取消时，不产生半条 AI 消息、不写入学习库、不记为成功复习。
- **AC-071-5**：短语比较为 P1，不作为 MVP 验收阻塞项。

#### FR-072 AI 上下文

- **AC-072-1**：默认发送时，请求只包含当前用户消息和显式勾选的附件；不包含之前会话消息。
- **AC-072-2**：用户打开“携带最近 N 条”后，预览显示具体消息条数和内容；请求只含这 N 条，默认关闭。
- **AC-072-3**：新建会话不自动携带旧会话内容；旧会话内容只能由用户显式重新添加。
- **AC-072-4**：移除某个附件后，预览和实际请求同步移除；预览内容与实际请求体一致。
- **AC-072-5**：任何情况下都不发送整部字幕、其他字幕、学习/复习历史、API Key 或文件路径；网络抓包可验证。

#### FR-091 千问模型配置

- **AC-091-1**：设置页显示可用模型列表和当前模型；默认经济型模型；选择后重启仍保持。
- **AC-091-2**：未配置 Key、模型不可用或模型 ID 无效时，显示明确错误；不发起调用。
- **AC-091-3**：经济型模型失败时，不静默切换到更贵模型；如提供切换，必须由用户确认。
- **AC-091-4**：每次调用记录实际模型 ID；历史记录和费用记录可对应到模型。

#### FR-092 费用记录/估算

- **AC-092-1**：每次成功调用记录时间、用途、模型、输入/输出字符数或 token 数（若 API 返回）、估算费用、币种、价格版本。
- **AC-092-2**：无法获得 token 用量时，明确标注“按字符估算”及估算方法；不得显示为精确账单。
- **AC-092-3**：按日/按会话汇总等于对应记录之和；刷新、重启后仍可查看。
- **AC-092-4**：失败/取消调用如产生供应商计费，记录实际或估算费用；未产生计费则不虚增；不得重复计数。
- **AC-092-5**：只有用户主动发起的调用才产生记录；启动、导入、浏览、复习不产生费用记录。

#### BR-SUB-08 统计口径

- **AC-STAT-1**：固定测试字幕的词次和去重词形数与 6.1.3 表一致；规则变更必须更新样本。
- **AC-STAT-2**：直撇号与弯撇号输入得到相同统计；大小写不影响去重键。
- **AC-STAT-3**：`don't` 为一个词形；`well-known` 为一个词形，`well known` 为两个；`John's` 与 `John` 为不同词形；`1999`、`[MUSIC]`、`JOHN:` 不计入。
- **AC-STAT-4**：全库去重词形数为跨字幕并集，不是各字幕去重数之和；学习库词条数单独计算。

#### BR-REV-04 / BR-REV-05 复习规则

- **AC-REV-1**：首次“记得”后 1 天到期；后续依次为 3、7、14、30 天；MVP 不出现 60/120/180 天。
- **AC-REV-2**：“模糊”按当前间隔减半（至少 1 天）；“忘记”为 1 天。
- **AC-REV-3**：同一天成功 3 次不算 3 个日期，不能掌握；3 个不同日期成功、至少一次距首次成功 ≥7 天、且最近一次成功，才标记已掌握。
- **AC-REV-4**：已掌握后出现“模糊/忘记”立即回到学习中，下次 1 天；历史记录保留。
- **AC-REV-5**：修改系统时钟/时区不产生重复日期或负数间隔；异常时按 EX-021 处理。

> 以上验收条件仍是建议；批准后写入 SRS，并在 `docs/05-测试与验收.md` 中转为测试用例。

## 6. 重点专项审核

### 6.1 字幕统计

#### 6.1.1 现有规则

BR-SUB-08 已定义：

- 词形由字母、词内撇号、连字符组成；
- 包含数字的字符串不计入；
- 非拉丁文字不计入；
- 长度至少 2 个字母，或为 `a` / `i`；
- 缩写和缩略形式按一个词形处理；
- 所有格保留；
- 不做词形还原；
- 停用词计入；
- 方括号内容和说话人标签不计入；
- 大小写不敏感，弯撇号规范为直撇号；
- 显示首次出现形式。

方向正确，但“缩写”需要拆开：

| 类型 | 例子 | 当前问题 | 建议规则 | 状态 |
| --- | --- | --- | --- | --- |
| 缩略形式（contraction） | `don't`、`it's`、`I'm`、`can't` | 未明确与“缩写”区分 | 一个词形；保留撇号；`it's` 与 `its` 不同 | 建议采纳 |
| 所有格（possessive） | `John's`、`teacher's` | 未明确是否与基础词合并 | 保留 `'s`；`John's` 与 `John` 两个词形 | 待用户批准 |
| 连字符复合词 | `well-known`、`long-term` | 与空格形式是否合并未定 | `well-known` 一个词形；`well known` 两个词形；不自动合并 | 待用户批准 |
| 带点缩写 | `U.S.`、`Mr.`、`e.g.`、`i.e.` | 句点会拆分，结果不稳定 | MVP：句点作分隔；单字母片段除 `a`/`i` 外不计；`U.S.` 记 0 个词，`Mr.` 记为 `mr`；接受这一噪声并写入限制 | 待用户批准 |
| 全大写缩写 | `TV`、`OK`、`FBI` | 未明确 | 作为普通词形计入；大小写不敏感 | 建议采纳 |
| 数字/混合 | `1999`、`MP3`、`B2B` | 已排除 | 含数字的整个字符串不计 | 建议采纳 |
| 非拉丁文字 | 中文、日文 | 已排除 | 不计英文词次；显示保留 | 建议采纳 |
| 单字母 | `I`、`a`、`U`、`S` | 只保留 a/i | 保留 `a`/`i`；其他单字母不计 | 建议采纳 |
| 停用词 | `the`、`a`、`to` | 已计入 | 计入；不自动删除 | 建议采纳 |
| 词形还原 | `run/runs/running/ran` | 不做 | MVP 分别统计；不引入 lemma；用户确认 | 待用户批准 |
| 说话人标签 | `JOHN:` | 已排除 | 行首全大写标签不计；显示保留 | 建议采纳 |
| 方括号说明 | `[MUSIC]` | 已排除 | 不计；显示保留 | 建议采纳 |

#### 6.1.2 统计定义

- 单字幕词次：所有有效 cue 中词形出现次数之和。
- 单字幕去重词形数：按规范化键去重后的数量。
- 全库词次：各字幕词次之和。
- 全库去重词形数：跨字幕去重键的并集数量。
- 学习库词条数：用户加入的词条数，与字幕词汇量不同。

建议在 SRS V0.2 中加一句：**“所有统计必须能用固定测试字幕复现；统计规则变更必须同步更新测试样本和验收条件。”**

#### 6.1.3 测试样本建议

| cue | 文本 | 计入词形 | 词次数 |
| --- | --- | --- | --- |
| 1 | `I don't think it's well-known.` | `i`, `don't`, `think`, `it's`, `well-known` | 5 |
| 2 | `Don't go! 1999` | `don't`, `go` | 2 |
| 3 | `[MUSIC] JOHN: Hello...` | `hello` | 1 |
| 4 | `Mr. Smith's U.S. trip` | `mr`, `smith's`, `trip`；`u.s.` 拆成单字母后不计 | 3 |

> 第 4 行体现带点缩写的已知噪声；如果用户不接受 `mr` 被统计，应增加一个小型缩写排除表（P1），而不是引入复杂 NLP。

#### 6.1.4 风险

- 不做词形还原会让 `run/runs/running/ran` 分散，学习库可能重复；这是统计口径选择，不是 bug。
- `well-known` 与 `well known` 不合并，可能导致重复词条；需用户确认。
- 带点缩写会产生 `mr` 等噪声；需接受或 P1 加排除表。
- 统计规则一旦写入数据，后续修改会影响历史统计；应在 P2 前冻结。

### 6.2 复习状态机

#### 6.2.1 状态与转换

| 状态 | 含义 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| 待学习（New） | 已加入学习库，未复习 | 用户加词/AI 确认保存单词 | 首次复习尝试 → 学习中 |
| 学习中（Learning） | 已开始复习，未满足掌握 | 首次尝试；或已掌握后失败 | 满足掌握规则 → 已掌握 |
| 已掌握（Mastered） | 跨日期验证通过 | BR-REV-05 | 后续“模糊/忘记” → 学习中 |
| 已归档（Archived，P1） | 用户主动移出复习 | 用户归档词条 | 用户恢复 → 按历史重算 |

#### 6.2.2 间隔建议

| 评分 | 初始间隔（MVP） | 后续实验（P1） | 说明 |
| --- | --- | --- | --- |
| 记得 | 1 天；之后 3、7、14、30 天 | 60、120、180 天 | 1/3/7/14/30 为初始配置，不声称最优 |
| 模糊 | `max(1, floor(当前间隔/2))` | 可调整 | 公式未验证；保留为实验规则 |
| 忘记 | 1 天 | — | 重置间隔；已掌握回退学习中 |

**与 SRS 的冲突**：BR-REV-04 当前包含 60/120/180 天；新方向只要求 1/3/7/14/30。建议：

- MVP 只实现 1/3/7/14/30；
- 30 天之后默认重复 30 天，或进入 P1 实验；
- 不把 60/120/180 写成 MVP 验收项；
- 在文档中明确“间隔规则是产品假设，不是已验证的最优学习算法”。

#### 6.2.3 掌握规则

当前 BR-REV-05：

1. 至少 3 次成功；
2. 至少 3 个不同本地日期；
3. 至少一次成功距首次成功 ≥7 天；
4. 最近一次成功；
5. 不允许手动设为已掌握。

与新方向一致。需要补充：

- **“成功”定义**：拼写正确，或词义回忆自评“记得”；“模糊/忘记”不算。
- **拼写错误**即使被用户上调为“模糊”，也不能算成功。
- **后续遗忘**：已掌握后出现“模糊/忘记”立即回到学习中，下次 1 天。
- **同日多次成功**只算一个日期。
- **表达练习**（P1）不计入成功。
- **测试方式**：可控日期注入；不能依赖真实等待 7 天。

#### 6.2.4 风险

- 无每日新词上限：用户可能一次积累过多，复习队列爆炸；建议界面显示数量，MVP 不设硬上限，P1 可加上限。
- “模糊”间隔公式未验证；不要把它宣传为科学算法。
- 词条归档 P1；字幕删除（FR-018）必须避免把词条、复习历史、语境变成孤立记录。
- 若删除字幕后强行删除词条和历史，会破坏审计；必须由用户确认，且默认归档。

### 6.3 AI 上下文边界

#### 6.3.1 现有规则

- 可选附件：当前 cue、词/短语、用户主动添加的相邻 cue；
- 同一会话历史可用于保持连贯；
- 发送前预览；
- 首次同意；
- 不发送整部字幕、学习历史、密钥；
- 会话本地保存、可删除。

#### 6.3.2 冲突

新方向要求“仅发送明确授权的必要上下文”。当前 BR-AI-03 允许自动携带同会话历史，用户可能只授权“当前这句话”，却把之前多条聊天一起发出去。这属于**范围扩大**，不是技术细节。

#### 6.3.3 建议规则

| 项目 | 建议 |
| --- | --- |
| 默认发送 | 当前用户消息 + 用户显式勾选的当前 cue/词/短语 |
| 会话历史 | 默认**不发送**；提供“本次携带最近 N 条消息”开关，默认关闭 |
| 开关展示 | 每次发送前显示将携带的消息数量；用户可逐条移除 |
| 新会话 | 不自动携带旧会话内容 |
| 附件 | 相邻 cue 默认不选；只有用户主动添加才发送 |
| 翻译/语境解释 | 只发送选中的 cue/词；不发送整部字幕 |
| 绝不发送 | 整部字幕、其他字幕、复习历史、每日记录、密钥、文件路径 |
| 历史保存 | 本地保存，可删除；删除会话不删除已保存学习条目 |
| 供应商保留 | 首次同意说明“千问可能按其政策处理/保留数据，应用不能保证云端删除” |

#### 6.3.4 费用与模型

新方向要求模型配置化和费用记录。建议最小需求：

- 用户可选择已配置的模型；默认经济型模型；
- 不在失败时静默切换到更贵模型；
- 每次调用记录：时间、用途、模型、输入/输出字符数或 token 数（若 API 返回）、估算费用、币种、价格版本；
- 若无法获得 token 用量，明确显示“按字符估算”，不伪装精确；
- 显示按日/按会话的累计估算；
- 不自动批量调用、不后台重试、不自动生成大量内容。

#### 6.3.5 AI 验收建议

- 网络抓包：启动、导入、浏览、复习、打开聊天但不发送 → 无千问请求。
- 发送预览与实际请求体一致。
- 关闭“携带历史” → 请求不含旧消息。
- 打开“携带最近 N 条” → 只含 N 条，且预览可见。
- 移除附件后，请求不含该附件。
- 删除会话后，已保存条目仍存在。
- 模型不可用时，不静默换贵模型。
- 费用记录与实际模型/用量一致；无法精确时明确标注估算。

### 6.4 异常处理

现有 28 个异常场景覆盖较全，但需调整：

| 异常 | 现状 | 建议 |
| --- | --- | --- |
| EX-006 重复导入 | 提供“作为新副本导入” | MVP 默认拒绝；副本降 P1，避免统计重复 |
| EX-022 字幕删除/归档 | 标为 P1/未决 | 提升为 P0，配合 FR-018；明确孤立记录防护 |
| EX-008 数据库损坏 | 通用描述 | 保留；用户提示恢复/备份，不静默清空 |
| EX-014 限流/配额 | 有提示 | 保留；增加费用/配额说明 |
| EX-021 日期/时区变化 | 有规则 | 保留；测试时钟回拨 |
| EX-023 提示词注入 | 有规则 | 保留；AI 输出只展示，不自动执行 |
| EX-029（新增） | 费用/用量数据不可得 | 显示“无法获取用量/按字符估算”，不伪造精确账单 |
| EX-030（新增） | 经济型模型不可用 | 显示错误，允许用户选择其他模型；不静默升级到昂贵模型 |

## 9. 仍存在的重大工程风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 本地 IPA 词典许可/覆盖不足 | P5 无法交付或存在法律风险 | 先确认可分发词典；缺失明确标记；不静默云端 |
| 千问价格/模型/用量不透明 | 费用记录不准、成本失控 | 经济型模型；费用估算标注不确定；不自动调用 |
| AI 上下文越界 | 用户隐私受损、信任下降 | 默认不发送历史；逐次预览；最小化附件 |
| 字幕删除产生孤立记录 | 词条/历史引用断裂 | 默认归档；硬删除需确认并冻结语境；不静默级联 |
| 复习算法未验证 | 学习效果不佳，用户误以为科学 | 标注为初始配置；P7 评估；不宣称最优 |
| 统计口径不稳定 | 同一字幕出现不同词数 | 冻结规则 + 固定样本 + 版本化 |
| 本地 HTTP 服务被跨站调用 | 本地数据被非预期操作 | 来源校验/等效防护；架构阶段验证 |
| 性能/数据规模未验证 | 大字幕卡顿、体验差 | 先测基线；P1 压测；不伪造指标 |
| 范围蔓延 | 短语比较/表达练习等未批准项膨胀 | P1 逐项批准；变更记录；MVP 退出标准 |
| 英语学习成效无法验收 | 软件完成但学习无效 | P7 独立基线/复测；不用功能完成度代替 |
| 无备份 | 本地数据丢失 | 文档说明数据位置；P1 备份 |

## 10. 建议的最小开发顺序

> 这是功能顺序，不是架构/数据库/API 设计。原则是先完成可离线验证的学习闭环，再接入云端增强；每一阶段仍应先写任务卡和验收条件。

1. **决策与验证 spike**：D-01 至 D-26 已批准并冻结于 SRS V0.2；仍需验证 IPA 词典许可/覆盖、千问模型/价格/用量字段。
