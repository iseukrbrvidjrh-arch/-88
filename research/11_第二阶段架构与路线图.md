# 第二阶段：架构与实施路线图

> **范围声明**：本文是方案路线图，不执行代码、迁移、配置变更或测试写入。A 的架构模式仅作设计参考，不直接复用其代码或 schema。

## 当前架构映射

保持 `api → services → domain` 的依赖方向：`app/main.py` 继续作为组合根；新增能力通过 API 路由、服务用例、领域规则、仓储和 integrations 端口接入。当前字幕和复习证据分别在 `app/services/subtitle_import.py`、`app/services/review.py`、`app/domain/review/rules.py`；AI 通过 `app/integrations/qwen_gateway.py` 隔离。

可借鉴 A 的 feature-first 和 facade repository 思想，但用 Python 的模块/Protocol 独立实现；不引入 Flutter/Drift。

## 路线

### P0 可靠性基线
建立 source/test/runtime 状态矩阵；在获批的隔离目录验证现有字幕、词汇、复习、AI 预览/取消、迁移与备份。出口：关键流程证据齐全，无数据损坏。

### P1 上下文连续性
改善 cue、词条、语境和继续学习的连续体验，保持离线能力；先不改数据库。出口：用户可从 cue 完成保存与复习，刷新/重启语义一致。

### P2 单一训练实验
选择听写或跟读；定义最小流程、隐私、存储、费用、学习假设和停止条件。出口：隔离数据可重放，失败可恢复，学习指标有基线。

### P3 provider 与导出
在 Qwen 稳定后评估 provider port、导出/恢复和缓存版本；不得绕过 send-plan。出口：成本和数据边界可审计。

### P4 平台扩展
只有在用户明确需要且前述指标达标后，才评估多媒体、多平台、账号或同步。

## 风险控制

大型字幕和媒体必须分页/限流；流式 AI 不得占用长数据库事务；录音需受控目录和删除策略；任何联网能力都保留同意和离线降级。每阶段都有 go/no-go，不以“已写代码”作为完成标准。
