# 第二阶段：信息架构与 UI 蓝图

> **范围声明**：本文为 UI/交互设计，不修改 `app/web` 或其他生产文件。以现有原生 JS/FastAPI 为渐进基线；不复制 A 的 Flutter 界面。

## 对象层级

学习库 → 字幕/媒体来源 → 字幕轨道 → cue → 当前学习上下文 → learning item → 复习活动；可选练习会话属于 cue 的附属对象，不取代 cue 和复习事实。

## 导航

1. **资料库**：导入、搜索、归档、继续学习。
2. **学习工作台**：左侧 cue/上下文，中心原文与操作，右侧词条/翻译/解释。
3. **词汇与语境**：条目、释义、来源、多个 cue 快照。
4. **复习**：今日队列、主动回忆、评分和历史。
5. **记录**：每日活动、掌握状态、学习趋势。
6. **设置与隐私**：云端同意、Key 状态、模型/费用、数据位置。

## 交互原则

- 当前 cue 在查词、保存、AI 预览和返回后仍可见。
- AI 不放在主学习动作之前；默认入口是理解和回忆。
- 所有异步操作有 loading、成功、失败、取消、重试状态。
- 空状态给下一步动作；重复导入显示原因；媒体缺失不删除字幕事实。
- 键盘：上下移动 cue，快捷键播放/朗读、保存、提交复习；焦点始终可见。
- 文本按不可信内容处理，避免不安全 HTML；错误消息不泄露路径、Key 或堆栈。

## 技术演进原则

现有 `app/web/app.js` 是单页状态机，适合先按页面/领域拆出状态与视图边界，但第二阶段不直接重写。只有在真实功能规模、可访问性或平台需求证明原生 JS 成本不可接受时，才重新评估 Flutter；不能因为 A 使用 Flutter 就迁移。
