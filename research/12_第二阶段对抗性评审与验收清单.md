# 第二阶段：对抗性评审与验收清单

> **范围声明**：本文是自审记录，不修改生产文件、数据库、配置、测试或用户数据。静态证据、测试文件和运行验证严格区分；未复制 enjoy_player 实现材料。

## 反方审查

| 质疑 | 结论/修正 |
|---|---|
| 是否变成通用播放器？ | 收紧为字幕优先，媒体只是可选上下文；不把播放器列为 P0。 |
| 是否把 A README 当已实现？ | 所有 A 功能标记为声称/静态证据，需运行验证。 |
| 新训练是否只是堆功能？ | 限制为一个实验，并要求主动回忆/复习指标和停止条件。 |
| 是否会破坏历史数据？ | 不改旧 review 语义；先逻辑模型，再隔离验证，再迁移。 |
| 原生 JS 是否失控？ | 先拆边界和验证，不立即换 Flutter；规模证据不足则不重写。 |
| AI/录音是否泄露隐私？ | 核心离线；每次联网显式预览；录音留存和删除必须决策。 |
| 是否忽视大数据性能？ | 设分页、限长、短事务和基准出口，不假设 SQLite 足够。 |
| 是否忽略许可证？ | AGPL-3.0 代码/资源/schema 不直接复用，必要时法律审查。 |
| 是否超出用户授权？ | 本阶段仅新增 research 文档，不进行开发或迁移。 |

## 阶段结论

方案可行，但推荐采用“保留 SceneLingo 核心、借鉴 A 的上下文和训练思想、一次只验证一个新闭环”的渐进路径。第二阶段交付标准是方案可追溯、可验收、可停止，不是功能完成。
